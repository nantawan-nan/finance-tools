# บรีฟ: ออกแบบหน้า "ทะเบียนคำสั่งซื้อ (Order Pipeline)" ใหม่

> เป้าหมาย: ทำให้หน้านี้ **เล่าสถานะของงานทั้งสายการขาย** ได้ในจอเดียว — เห็นปัญหาเร็ว · กดเข้าจัดการเร็ว · ไม่หลงทางระหว่างแท็บ
> ส่งบรีฟนี้ + สกรีนชอตหน้าจอปัจจุบันให้ AI ดีไซน์ (Claude.ai) เพื่อขอ HTML + CSS ใหม่

---

## 1) หน้านี้มีไว้ทำอะไร

หน้า **ทะเบียนคำสั่งซื้อ** คือ "ศูนย์กลางตรวจงานด้านรับ" ของบริษัท — รวมข้อมูลจาก 3 แหล่ง:

1. **ระบบ BigSeller** — ออเดอร์ E-commerce (Shopee/TikTok/Lazada) + ออฟไลน์ (FACE/LINE/Dealer)
2. **ระบบบัญชี Express** — IV (ใบกำกับภาษี/Invoice) ที่บัญชีคีย์เข้าระบบแล้ว
3. **หลังบ้านแพลตฟอร์ม** — รายงาน Shopee/TikTok/Lazada (สำหรับเทียบยอดขาย)

**คำถามที่หน้านี้ต้องตอบในจอเดียว:**
- รวมขายไปทั้งหมดกี่ออเดอร์ / กี่บาท
- มีออเดอร์กี่ตัวที่ **ยังไม่คีย์ IV** เข้า Express → ต้องส่งบัญชีคีย์
- มีออเดอร์กี่ตัวที่ **คีย์ IV แล้ว** แต่ **ยอดไม่ตรงกัน** ระหว่าง BigSeller ↔ Express → ต้องตรวจ
- หลังบ้านแพลตฟอร์มมีออเดอร์ที่ **BigSeller ไม่มี** (ขายคีย์ไม่ครบ) หรือเปล่า
- งานปิดไปแล้วกี่ % (คีย์ IV ครบ + ยอดตรง)

> เจ้าของใช้แคปหน้าจอนี้ส่งสรุปงานทุกวัน — ต้องอ่านชัด สวยพอจะส่งผู้บริหารดูได้

## 2) โครงสร้างหน้าปัจจุบัน (บนลงล่าง)

1. **Hero band** — โลโก้บริษัท + ชื่อหน้า "ทะเบียนคำสั่งซื้อ" + คำอธิบาย + ยอดออเดอร์รวมขวาบน
2. **ช่องค้นหาแบบรวม** — พิมพ์เลขออเดอร์ / IV / RE / BQ / ชื่อลูกค้า / SKU → เด้งสถานะออเดอร์ทันที
3. **Action bar** — ปุ่ม "อัปรายงานขาย BigSeller" · "ส่งออกออเดอร์ยังไม่คีย์ IV" · "ล้างทะเบียน เริ่มใหม่"
4. **KPI 4 ใบ** (สำคัญที่สุดของหน้านี้)
   - **คำสั่งซื้อจากระบบ BIG SELLER** (gradient brand) — จำนวนออเดอร์ทั้งหมด + ยอดเงิน
   - **ต้องดำเนินการ** (soft-red) — รอคีย์ IV + ยอดไม่ตรง
   - **รอเทียบ / หลังบ้านขาด** (soft-amber) — รอเทียบยอดหลังบ้าน หรือ BigSeller ขาด
   - **ปิดงานแล้ว** (soft-green) — % ที่ปิดงานแล้ว
5. **แท็บ (Tabs)** — 5 แท็บ:
   - 📊 **สรุปสถานะ** (default) — funnel + กราฟรายเดือนต่อแพลตฟอร์ม
   - 📋 **คำสั่งซื้อจากระบบ Big Seller** (922) — ตารางออเดอร์รายตัว
   - 🧾 **IV จาก EXPRESS** (206) — รายการ IV ที่บัญชีคีย์
   - 🔎 **คัดกรองและนำเข้า IV** — ตรวจ IV ที่ยังไม่ tag เข้าออเดอร์
   - (ค้นหา — global search ผ่านช่องบนสุด)
6. **เนื้อหาแท็บปัจจุบัน (สรุปสถานะ):**
   - การ์ด "ออเดอร์ทั้งหมด" + breakdown (ใช้งาน / ยกเลิก / 922+74=996)
   - **แถบสัดส่วนสถานะ** (stacked bar เต็มความกว้าง) — รอเทียบยอดขาย / รอคีย์ IV / คีย์ IV แล้ว รอรับชำระ / ยกเลิก
   - การ์ดสถานะ 4 ใบ (รอเทียบยอดขาย / รอคีย์ IV / คีย์ IV แล้ว / ยกเลิก) — % + ยอดเงิน
   - **กราฟแท่งรายเดือนต่อแพลตฟอร์ม** — แท่งโปร่ง = ทั้งหมด · แท่งทึบ = คีย์ IV แล้ว

## 3) 🎯 ปัญหาปัจจุบัน (สิ่งที่อยากให้ดีไซน์แก้)

### 3.1 ลำดับความสำคัญไม่ชัด
- KPI 4 ใบโดดเด่นเท่ากันหมด ไม่รู้ว่า **"ต้องดำเนินการ 147"** = งานเร่งสุด หรือ **"ปิดงานแล้ว 0%"** = ดูเล่น ๆ
- เลขใหญ่ดู KPI แล้วยังไม่เห็นว่า **ต้องไปทำอะไรต่อ** (ไม่มี CTA ชี้ทาง)

### 3.2 แท็บกับ KPI ไม่ผูกกัน
- KPI "ต้องดำเนินการ 147" คลิกแล้วต้องไปเองที่แท็บไหน? ผู้ใช้สับสน
- จำนวนใน chip ของแท็บ (922 / 206) ตีกับเลข KPI ไม่ตรง → งง

### 3.3 funnel/กราฟรายเดือนใหญ่เกินไป
- แท็บ "สรุปสถานะ" เลื่อนลงเยอะมาก กว่าจะถึงกราฟรายเดือน
- แถบสัดส่วนสถานะ + การ์ดสถานะ 4 ใบ = **บอกข้อมูลเดียวกัน 2 แบบ** เปลืองพื้นที่
- กราฟรายเดือนแยก 2 อัน ("ยอดขายต่อแพลตฟอร์ม" + "สรุปรายเดือนต่อแพลตฟอร์ม") ดูซ้ำ

### 3.4 ไม่เห็นภาพ "สายงาน" (pipeline)
- จริง ๆ แล้วงานคือ flow ต่อเนื่อง: **ขาย → คีย์ IV → รับชำระ → เงินเข้าแบงค์**
- ตอนนี้แสดงเป็นการ์ดแยก 4 ใบ ไม่เห็นว่ามันคือสเตปต่อกัน
- อยากเห็นเป็น **funnel/pipeline visual** ที่บอกได้ว่าออเดอร์ติดอยู่ขั้นไหน

### 3.5 ปุ่มในแถวเดียวกันโทนต่างกันมาก
- "อัปรายงานขาย BigSeller" (น้ำเงินทึบ) + "ส่งออก..." (โปร่ง) + "ล้างทะเบียน..." (แดง) อยู่แถวเดียวกัน
- ปุ่มอันตราย (ล้าง) ไม่ควรอยู่ใกล้ปุ่มใช้งานหลัก

### 3.6 หลายแท็บที่ทำงานคล้ายกัน
- "คำสั่งซื้อจากระบบ Big Seller" + "IV จาก EXPRESS" + "คัดกรองและนำเข้า IV" — 3 แท็บนี้คือ **3 มุมของข้อมูลชุดเดียวกัน**
- ผู้ใช้ใหม่งงว่าควรเข้าแท็บไหนเพื่อทำงานอะไร

## 4) สิ่งที่อยากได้ในเวอร์ชันใหม่

### 4.1 Hero/หัวที่ "บอกสุขภาพงาน" ในบรรทัดเดียว
ตัวอย่างเล่าเรื่อง:
> "วันนี้ขายไป **922 ออเดอร์ · 385,860 บาท** · ปิดงานแล้ว **77.7%** · เหลือ **147 ออเดอร์ต้องคีย์ IV**"

### 4.2 KPI ใหม่ — เน้นความเร่งด่วน + CTA
4 ใบเหมือนเดิมแต่:
- ใบ "ต้องดำเนินการ" = **ใหญ่ที่สุด** (hero card) + ปุ่ม "ดูรายการ →" คลิกแล้วเข้าแท็บที่ filter พร้อม
- ใบ "ปิดงานแล้ว" = แสดงเป็น **progress ring** แทนเลข % ตัวเดียว
- ทุก KPI ใบ = คลิกได้ + hover เห็นว่า "คลิกจะไปไหน"

### 4.3 Pipeline view (แทน funnel + การ์ดสถานะคู่กัน)
อยากได้ **horizontal pipeline** 4 ขั้น:

```
[ ขาย ]──→[ คีย์ IV ]──→[ รับชำระ ]──→[ เงินเข้าแบงค์ ]
  922       775           716            0
            ↑ ค้าง 147
```

แต่ละขั้น:
- จำนวนออเดอร์ + ยอดเงิน
- ขั้นที่มีของค้าง = highlight สีอำพัน/แดง + badge "ค้าง N"
- คลิกขั้น = filter แท็บ "คำสั่งซื้อจากระบบ Big Seller" ตามสถานะนั้น

### 4.4 Action bar แยกชัด
- **กลุ่มซ้าย** (primary actions): อัปไฟล์ BigSeller · ส่งออกออเดอร์ยังไม่คีย์ IV
- **กลุ่มขวา** (destructive/setting): ล้างทะเบียน (icon เท่านั้น · ต้อง confirm 2 ชั้น)

### 4.5 ยุบ 3 แท็บข้อมูลเป็น 1 มุมมองตาราง + filter
แทน "Big Seller / IV จาก EXPRESS / คัดกรอง IV" → ให้เป็น **ตารางออเดอร์เดียว** + chip filter ด้านบน:
- 🔵 ทั้งหมด (922)
- 🟡 รอคีย์ IV (147)
- 🔴 ยอดไม่ตรง (3)
- 🟢 ปิดแล้ว (716)
- ⚫ ยกเลิก (74)

แต่ละแถวมีคอลัมน์: วันที่ · เลขออเดอร์ · แพลตฟอร์ม · ลูกค้า · ยอด BigSeller · ยอด IV · ส่วนต่าง · สถานะ (badge)

(แท็บ "สรุปสถานะ" คงไว้สำหรับภาพรวม + กราฟ)

### 4.6 กราฟรายเดือนกะทัดรัด
- รวม "ยอดขายต่อแพลตฟอร์ม" + "สรุปรายเดือนต่อแพลตฟอร์ม" เป็นกราฟเดียว (stacked bar) — โปร่ง = ยังไม่คีย์ IV / ทึบ = คีย์แล้ว
- มี toggle: "ดูเป็นยอดเงิน / จำนวนออเดอร์"

### 4.7 Empty / loading / error state
ออกแบบ 3 state ให้ด้วย:
- **ว่าง** (ยังไม่ได้อัปไฟล์) — illustration + ปุ่ม CTA
- **โหลด** — skeleton ของ KPI + ตาราง
- **error** — กล่องอ่อนโยน + ปุ่มลองใหม่

## 5) 🎨 แบรนด์ & ข้อจำกัด (สำคัญ — ต้องบอก AI)

- **ภาษาไทยเป็นหลัก** ฟอนต์ **IBM Plex Sans Thai** (ไทย) + IBM Plex Sans (อังกฤษ/ตัวเลข)
- 2 ธีมสีตามบริษัท:
  - **M Bark = navy `#1e3a8a`** (อย่างในสกรีนชอต)
  - **Benya = teal `#0d9488`**
  - สลับด้วย `body[data-co="mbark"]` / `body[data-co="benya"]`
- สีสื่อความหมาย:
  - เงินเข้า / สำเร็จ `#14B8A6` (เขียว teal)
  - เงินออก / ยกเลิก `#E18AAA` (ชมพู)
  - ต้องทำ / เร่งด่วน แดง `#dc2626`
  - ระวัง / รอตรวจ เหลืองอำพัน `#f59e0b`
- โทนปัจจุบัน: **Finance OS style** — การ์ดขาวมุมโค้ง 12-20px · เงาเบา · พื้นหลังเทาอ่อน `#f8fafc` · ไม่ใช้ glassmorphism หนัก (เน้นอ่านง่ายเพื่อแคปส่ง)
- Icon: **Lucide** ผ่าน `<i data-lucide="ชื่อ">` (เช่น `package`, `file-check`, `wallet`, `landmark`)
- ค่าติดลบใช้วงเล็บ `(1,234.00)`
- ตัวเลขเงินใช้ฟอนต์ tabular (`font-variant-numeric: tabular-nums`)
- ใช้งานจริง = แคปภาพอ่านบนมือถือ/Desktop → ต้องอ่านชัดในภาพนิ่ง · จัด layout 1440px กว้างได้
- **เว็บไฟล์เดียว vanilla JS ไม่มี framework** → ขอผลลัพธ์เป็น **HTML + CSS ล้วน** (ห้าม React / ห้าม Tailwind build step / ใช้ inline `<style>` ได้)

## 7) สิ่งที่ขอจาก AI ดีไซน์

1. ออกแบบ **ทั้งหน้า** ใหม่ตามโครงสร้างในข้อ 4
2. ส่งเป็น **ไฟล์ HTML + CSS เดียว** เปิดในเบราว์เซอร์ดูได้เลย (ใส่ mock data ตามข้อ 6)
3. ทำ **2 ธีม** (M Bark navy / Benya teal) สลับด้วย `body[data-co]`
4. ใช้ **Lucide icon** + ฟอนต์ **IBM Plex Sans Thai**
5. ออกแบบให้ **สวยตอนแคปเป็นภาพ** (ไม่พึ่ง hover ในการอ่านข้อมูลหลัก)
6. ขอ **3 state**: ปกติ (มีข้อมูล) · ว่าง (ยังไม่อัปไฟล์) · loading (skeleton)
7. ส่งคืน **2-3 variant** ของส่วน "Pipeline view" (ข้อ 4.3) ให้เลือก

## 8) Don'ts (สิ่งที่ห้ามทำ)

- ❌ ห้ามใช้ React / Vue / framework — ขอ vanilla HTML+CSS
- ❌ ห้ามใช้ Tailwind ที่ต้อง build (ใช้ utility class แบบเขียนเองได้ แต่ต้องอยู่ใน `<style>` ในไฟล์)
- ❌ ห้ามใส่ emoji ใหญ่แทน icon (ใช้ Lucide)
- ❌ ห้ามใส่ animation เด้งแรง ๆ — งานเงิน ต้องดูเป็นทางการ
- ❌ ห้ามทำ dark mode (ทำแค่ light mode 2 ธีม)
- ❌ ห้ามใช้รูปธนาคาร/โลโก้แพลตฟอร์มจาก CDN ภายนอกที่ไม่รู้จัก — ใช้ Lucide icon แทนได้
